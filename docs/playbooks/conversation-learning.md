# Conversation learning

## Goal

Turn five substantive AI conversations into useful business evidence without moving private conversation content into GitHub.

## Storage boundary

The repository contains blank templates and aggregate process only.

- Keep each completed conversation debrief in a private working location.
- Never commit completed debriefs, transcripts, recordings, participant names, organizations, contact details, exact quotations, or distinctive facts.
- A completed five-conversation synthesis may enter GitHub only after it is aggregate, anonymous, and safe against re-identification.
- Feedback permission and testimonial permission remain separate from this learning process.

If a detail is necessary to recognize the person or situation, it is too specific for the repository.

## Workflow

### After each substantive conversation

Within 24 hours:

1. Duplicate the [private conversation debrief](../templates/conversation-debrief.md) outside the repository.
2. Remove names and unnecessary identifying context before writing reflections.
3. Select one primary question code and up to two secondary codes.
4. Select the observed constraints and the strongest outcome code.
5. Record whether a clear next action, owner, and timing emerged.
6. Keep direct feedback in its existing private system; do not copy it into the debrief unless needed for the private reflection.

### After five conversations

1. Create a private copy of the [five-conversation synthesis](../templates/five-conversation-synthesis.md).
2. Count codes and outcomes without copying the individual notes.
3. Report themes only when they appear in at least two conversations.
4. Generalize or omit any combination of details that could identify a participant.
5. Choose one next move: resource, article, offer experiment, process change, or no change yet.
6. Add only the safe aggregate summary and decision to issue #4.
7. Update the decision log in `OPERATING.md` if positioning or delivery changes.

## Coding rubric

Choose the closest code based on the decision the person was trying to make, not merely the technology they mentioned.

### Question code

| Code | Use when the central question is about |
| --- | --- |
| `strategy` | Whether or where AI belongs in a goal, organization, or life |
| `workflow` | Changing a repeated process or handoff |
| `tool_selection` | Choosing among tools, models, vendors, or approaches |
| `evaluation` | Knowing whether a system works or is trustworthy |
| `adoption` | Helping people understand, accept, or use a system |
| `risk` | Privacy, safety, security, governance, or failure modes |
| `meaning` | Agency, embodiment, judgment, identity, or broader human implications |

### Constraint code

| Code | Use when progress is limited by |
| --- | --- |
| `unclear_outcome` | No observable definition of success |
| `data` | Missing, inaccessible, low-quality, or sensitive data |
| `integration` | Existing systems, handoffs, or technical dependencies |
| `capability` | Skills, time, or implementation capacity |
| `trust_governance` | Approval, safety, privacy, accountability, or confidence |
| `budget_timing` | Cost, priority, procurement, or deadline |
| `ownership_adoption` | No clear owner or likely user behavior blocks progress |

### Outcome code

Choose one strongest outcome:

| Code | Evidence at the end of the conversation |
| --- | --- |
| `reframed` | The person can state a clearer problem or decision |
| `decided` | A proceed, pause, stop, or selection decision was made |
| `next_experiment` | A bounded test and its evidence were defined |
| `resource_or_referral` | A specific resource, introduction, or specialist is the right next step |
| `no_clear_next_step` | The conversation did not produce a usable next move |

## Quality rules

- Use one primary question code; excessive coding hides the real pattern.
- Separate what the participant said from Matthew's interpretation in the private debrief.
- Do not treat politeness as evidence of value.
- Prefer observable evidence: a decision, a changed framing, a defined experiment, or an agreed next action.
- Do not claim a trend from one conversation.
- Five conversations are an early signal, not market validation.
